# AI 产品拆解（ai-product-teardown）

> 用运营视角拆解 AI 产品：不只看「它有什么功能」，更看「它为什么这样设计、运营在推什么力、指标在验证什么假设」。

## 🎯 为什么做拆解

产品运营岗的核心能力之一是**把一个产品还原成「目标—路径—指标」的决策链**。拆解是我训练这个能力的方式：每篇拆解回答四个问题——

1. 这个产品在解决谁的什么问题？（定位与用户）
2. 它用什么路径解决？（核心流程与功能）
3. 它靠什么增长和留住用户？（运营机制与指标）
4. 如果我是产品/运营负责人，我会怎么做？（问题与机会）

## 🔍 拆解方法论：五层框架

```
第一层 定位层    解决谁的问题？替代了什么旧方案？差异化在哪？
第二层 用户层    核心用户画像与使用场景；用户旅程的关键触点
第三层 功能层    核心流程拆解；功能与用户任务的对应关系
第四层 运营层    增长机制、激励体系、内容/生态运营策略
第五层 指标层    猜测北极星指标与关键过程指标；当前策略在验证什么假设
```

**拆解原则：**

1. **区分事实与推测**：功能流程是可观察到的事实；指标和策略意图是推测，必须标注「猜测/假设」
2. **运营视角优先**：同一个功能，产品视角看「怎么设计的」，运营视角看「怎么被用起来的」——后者是拆解的增量价值
3. **必须落到自己的建议**：没有「如果是我怎么做」的拆解只是资料整理，建议质量才是思考深度的证明

## ⚠️ 说明

- 所有拆解基于**公开信息 + 个人体验**撰写，涉及数据均为公开报道或个人估算，已在文中标注
- 拆解仅代表个人分析，与任何公司立场无关
